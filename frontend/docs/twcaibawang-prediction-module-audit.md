# twcaibawang 预测资料模块盘点

本清单只针对 `frontend/public/vendor/twcaibawang.com/index.html` 首页当前可见资料区，目标是回答两件事：

1. 哪些模块可以直接复用现有后端预测机制与公开接口
2. 哪些模块还需要新增或扩展后台 API / 内容模型

## 1. 当前结论

`twcaibawang(web_id=5)` 第二阶段不建议直接把整页所有资料块一次性动态化。

更稳妥的方式是分三类推进：

1. 先接“已确认可映射”的标准预测模块
2. 再处理“需要文章/详情内容接口”的栏目
3. 最后处理“页面结构是组合型、现有 payload 不完全匹配”的复杂静态块

## 3. 需要文章/详情内容接口的模块

这类模块不是标准预测历史行，更像“栏目列表 + 详情页”：

| 首页块 | 当前形态 | 现状 | 建议 |
| --- | --- | --- | --- |
| 高手榜单 | 列表跳详情页 | 首页链接到 `11169.html` ~ `11184.html` | 需要文章列表接口 + 详情接口 |
| 详情资料页 | 静态 HTML | 当前仍是 vendor 静态页 | 可先继续静态托管，后续再做 CMS 化 |

建议新增的后端能力：

1. `GET /api/vendor/articles?site_id={site_id}&category={category}&term={term}`
2. `GET /api/vendor/articles/{slug}`

建议最小字段：

- 列表：`id`, `slug`, `title`, `term`, `category`, `href`, `updated_at`
- 详情：`id`, `slug`, `title`, `html`, `text`, `source_file`

## 4. 需要新开发或扩展 payload 的复杂模块

这类块不是简单“单模块一条 content”，而是一个块里组合了多组维度，现有后端机制只能覆盖其中一部分。

| 首页块 | 当前问题 | 建议 |
| --- | --- | --- |
| 五肖五码 | 一个块同时包含 五肖/四肖/三肖/二肖 + 五码/四码/三码/二码 | 需要专属 payload 结构，不能直接套现有单机制 |
| 一肖一码 | 一个块同时包含 九肖/七肖/五肖/三肖 + 14码/8码/5码 + 最终一肖一码 | 需要组合型模块 API 或专用 mode |
| 输尽光 | 页面块已知，但还未确认真实 mode_id / payload 结构 | 先查 PostgreSQL 现有表再决定 |
| 六尾中特 | 需要确认真实六尾数据来自哪个 mode_id | 先查 `mode_payload_tables` 和历史数据 |
| 四行中特 | 当前后端已有 3行机制，没有确认 4行同构机制 | 可能需要新机制或扩展现有机制 |
| 绝杀10码 | 页名清楚，但还没确认后台真实 source mode | 先做 source-table 盘点 |
| 双波10码 | 现有 `shuangbo` 只覆盖双波命中，不覆盖“10码”组合格式 | 需要专用 payload |
| 家野各三肖 | 需要确认是否已有同构多列机制 | 先查表结构 |
| 大小+2头 | 当前现有机制分散在 `daxiao` / `liangtouzxt` / `dxztt1`，但首页块是组合展示 | 可能需要聚合模块 |

## 5. 推荐的后端开发优先级

建议按下面顺序推进，而不是按首页从上到下硬改：

1. 先配置 `twcaibawang` 站点蓝图，只启用已确认可映射模块
2. 再做“高手榜单”文章列表 / 详情接口
3. 再对复杂块逐个查 PostgreSQL 真实 source mode / payload
4. 只有确认数据库里已有同构数据后，才做 Next 页面动态化
5. 如果数据库没有同构数据，再决定是：
   - 新增 `mechanism_key`
   - 新增 `mode_id`
   - 还是新增“组合型模块 API”

## 6. 当前建议新增的后台能力清单

### 可以直接复用，无需新增

- `/api/public/latest-draw`
- `/api/public/next-draw-deadline`
- `/api/public/draw-history`
- `/api/public/site-page`
- `/api/legacy/post-list`
- `/api/predict/[mechanism]`

### 建议新增

1. 文章列表接口
2. 文章详情接口
3. 组合型首页资料块接口
   - 优先用于 `五肖五码`
   - 优先用于 `一肖一码`
4. 未确认块的 source-mode 审计脚本或后台查询页

## 7. 当前建议的站点蓝图策略

当前仓库里已经补了一个保守版 `twcaibawang` 站点蓝图草案，特点是：

- 只覆盖“已确认可映射”的模块
- 不会影响其他站点
- 不会修改现有公共 API 结构
- 会把未确认资料块作为 `blocked_frontend_items` 暴露出来，方便后台盘点

这意味着你现在可以先把 `twcaibawang` 的模块同步跑起来，但不会误把那些结构不清楚的块假装成“已完成动态化”。
