### 渲染链路证据

1. `site-data-adapter.js` 中的 `SECTION_CONTRACTS` 为 19 项模块声明 `classification: "mapped"`、
   `moduleKeys` 和 `rendererName`；例如单双各四肖使用 `danshuang4xiao` 与
   `renderFourXiaoOdds`。
2. `selectLottery()` 调用 `LotterySiteDataClient.loadPredictions({ lotteryType, historyLimit })`；
   data client 将其构造为上述 `GET prediction-modules` 请求。
3. `renderPredictions()` 调用 `moduleMap()` 和各 named renderer；运行后表格行出现
   `data-prediction-row="0"...`，这是源码供应商快照不存在的属性。
4. `index.html` 源码仍含大量静态 `060期` 和 `.bizhong1` 数字，因此“源码含静态快照”不能单独证明
   已映射模块最终可见内容是硬编码；必须与运行后 DOM 和网络响应一起判断。

## 接近度评分

**总体接近度：46 / 100。**

评分方法：数据动态化 30 分、DOM 结构/层级 30 分、格式与分组 20 分、命中/空态 10 分、
静态快照清理 10 分。

| 维度 | 得分 | 依据 |
| --- | ---: | --- |
| 动态数据接入 | 25 / 30 | 19 个映射模块有统一 API、期号与抽样内容可对应；24码仍静态。 |
| DOM 结构/层级 | 8 / 30 | 表格、类名、卡片外壳多保留，但多个 renderer 把整行写成单一文本，内部叶级层级失效。 |
| 格式与分组 | 6 / 20 | 单双分组、家/野两栏、④肖八码两行、22码两行、杀波语义、七尾/七码分隔均有明显偏差。 |
| 命中与空态 | 4 / 10 | 有 `对/错` 和待开奖，但黄色命中叶节点没有填充；24码没有空态。 |
| 静态快照清理 | 3 / 10 | 已映射表格的可见期号已更新；24码九张卡和组合区的静态数据/占位仍未完成清理。 |

主要扣分点：**一头一码完全静态、renderer 未按原 HTML 的最小叶节点写入、多个复杂模块丢失原始
分组和换行、部分模块的 API 字段与原标题语义不一致。**

## 优化建议

1. 优先实现 `one_head_one_code_24` 的后端生成、站点授权和 renderer；在实现前立即清空九张
   `.bizhong1` 的期号、号码与黄色快照，显示命名空态。
2. 重写 `renderFourXiaoOdds`，分别填“单肖”和“双肖”两个 `.zl`，并对命中特别号生肖使用已有
   黄色 `<span>`；禁止对 `<td>` 做整行文本写入。
3. 为家禽VS野兽、④肖八码、精选22码、稳杀七码、七尾中特和一句话模块建立专用 renderer，严格写入
   基线中记录的每个字段和 `<br>` 槽位；同时修正 `title_14`、`4xiao8ma`、`title_74` 的结构化
   `prediction.extra`，不要依赖模糊 `tokens`。
4. 对绝杀①半波先核实模块实际语义：若 API 提供的是“半波（红单等）”而基线要求“波色（红波等）”，
   应改为 `unavailable` 或新增匹配机制，不能展示为同一模块。
5. 为全部 19 个模块及 24码空态增加浏览器 DOM 契约：断言 API 字段到具体叶节点的对应、保留标签/
   分隔符/`br`、黄色命中、没有静态期号快照。现有“页面包含 API 请求”的测试不能替代该验证。
