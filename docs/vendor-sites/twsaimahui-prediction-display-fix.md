## 三、`res_code` / `res_sx` 索引映射的验证证据（先验证后写码）

### 3.1 数据来源链路

1. 表 `public.mode_payload_197` 每个**期号一行**，字段 `term`、`res_code`、`res_sx`、`content`。
2. 前端兼容层 `frontend/app/api/kaijiang/[[...path]]/route.ts`：
   - `filterSanqiDisplayRows()`（L528–618）按 `start-end` 分组，只保留「窗口内**已开奖且期号最大**的一行」
     （`latestDrawn`），把它作为该窗口的代表行；窗口内其它期的行被丢弃；
   - `mapSanqiTwsaimahui()`（L820–842）把该代表行的 `res_code` / `res_sx` 原样透出。
3. 因此 `/api/kaijiang/getSanqiXiao4new` 返回的 `res_code`/`res_sx` 是**某一期的完整 7 个开奖号码**，
   第 1 项是特码/特肖，而非三期拼接。

### 3.2 逐期直连核对（决定性证据）

用 `lottery_draws`（`lottery_type_id=3`）做全表比对，`web=6` 的三条已开奖窗口：

| 窗口 `name` | `res_code` | 与 `lottery_draws.numbers` 完全一致的期 | 是否等于窗口最新期 |
| --- | --- | --- | --- |
| 188-190 | `20,19,38,35,23,42,45` | **2026 年 190 期**（正序完全一致） | 是 |
| 185-187 | `03,28,07,20,39,30,29` | **2026 年 187 期** | 是 |
| 182-184 | `24,41,05,09,35,20,21` | **2026 年 184 期** | 是 |
| 191-193 | （空） | — | 该窗口未开奖 |

同时反向确认：`lottery_draws` 中 188/189 期的真实开奖 `07,27,02,36,49,45,38`、`32,36,39,05,33,37,09`
**不在** `res_code` 里，说明接口没有把三期号码拼在一起。

## 五、逐模块修复说明

### 1. `068chengyupw.js`（成语平特尾，`.l20`）
- **问题**：`开:${codeSplit[index]||code||'00'}`，`index` 找不到时为 `99`（数组无此项）→ 回退到
  `code`（列表最后一个码），判错期也会显示一个真实号码；完全缺少高亮。
- **修复**：解析成语首字得到目标尾数 `num`；判定 `opened && code尾数 === num`。
  命中时把本期特码标黄并显示「准」，未命中显示「错」并显示真实 `开:生肖+号码`；
  未开奖显示 `开:待开奖`、无准错、无高亮。
- 例：190 期 `零珠片玉`（零 → 尾 0），特码 20 尾 0 → `开:猪20准`，`20` 标黄；
  189 期 `一行作吏`（一 → 尾 1），特码 32 尾 2 → `开:猪32错`，无高亮。

### 2. `023sanqibizhong.js`（四肖三期内必出，`.l21`）
- **问题**：整块是供应商静态样例——固定 `龙马羊狗`、固定 `开:猫00`/`开:蛇12`/`开:虎27`。
- **修复**：
  - 候选四肖改为从 `safeParseJSON(d.content, [])` 的每项 `"肖|码,码,码,码"` 取 4 个生肖，渲染到中间单元格；
  - 三个期号来自 `d.name`（`"191-193"`）：`names[0]` 最早、`names[1]` 最晚、中间期 = 最小期 + 1 且保持补零宽度；
  - 开奖结果取 `codeSplit[0]` / `sxSplit[0]`（§三已验证），命中（特肖 ∈ 候选四肖）→ 该生肖标黄 + 显示「准」，
    未命中 → 「错」，未开奖 → 只显示期号、不显示准/错、不高亮。
- **未能完全满足的一点（明确说明）**：任务描述希望「每期真实开奖」都显示，但接口对每个窗口
  **只透出一期的开奖数据**（§3.1 的 `filterSanqiDisplayRows` 只保留 `latestDrawn` 一行；
  `res_code`/`res_sx` 只含该期的 7 个号码，不是三期拼接）。
  因此代码只在**窗口最新期**显示 `开:生肖+号码` 与准/错，另两期只显示期号——
  这是按规范「没有可靠数据时不编造判定」的选择，而不是猜测期号归属。
  要真正做到逐期显示，需要后端/兼容层新增逐期结果接口（超出「不碰预测数据生成逻辑」的授权范围，未做）。

### 3. `035ma16.js`（16 码中特，`.l29`）

## 六、未能修好 / 需要后续处理的项目

### 1. `.l21`（023）只能显示窗口最新一期的开奖结果
- **原因**：接口每个窗口只透出一期的 `res_code`/`res_sx`（§3.1、§5.2）。
- **影响**：另两期只显示期号，不显示开奖与判定（不违反规范，但信息比原型样例少）。
- **建议**：在兼容层新增逐期结果接口（或让 `mapSanqiTwsaimahui` 透出窗口内各期结果），前端再逐期判定。

### 2. 上游数据竞态：窗口 `(start, end)` 与 `content` 可能错配
- **现象**：连续两次抓取中，`.l21` 的 `191-193` 窗口先显示候选 `兔马羊狗`，后变成 `牛马狗鼠`
  （后者实为 `188-190` 窗口的候选），且 `192`/`193` 期的行被置空。
- **原因**：`start`/`end` 是「后来回填的窗口字段」，而 `content` 是按行写入的；
  当同一 `mode_payload_197` 窗口出现多行（term 191/192/193），`filterSanqiDisplayRows`
  选中的代表行会随写入时序变化，导致 `name` 与 `content` 可能来自不同批次。
- **影响**：页面可能显示「用 A 窗口的候选 + B 窗口的开奖」，属于展示层无法根治的问题。
- **建议**：由后端在生成/回填时保证同一窗口各行的 `content` 一致，或让兼容层按 `term` 而非
  `start-end` 组装窗口。**未在本任务处理**（涉及预测数据生成逻辑，且不在授权范围内）。

### 3. 其它模块的未开奖占位文本（不在本次范围）
全页面扫描后，`191` 期未开奖的占位文本仍存在于**未被本次授权的模块**中，例如：

- `191期家畜野兽:【马狗蛇鼠+…】 开:？00??`（`.box.l12` 等）
- `191期左右生肖:左肖 开:？00??`（`.box.l2`）
- `【台湾】191期：六肖三码 开:？00`（`#hao012`）
- `191期绝杀一肖:【蛇】开:？00错`（`.box.l40`，即审计唯一残留的 `R2` warn）
- `#table400916271`、`.l67` 等既有模块

共 48 行含 `？00`。这些模块**不在本任务给定的修复清单**内，本次未改动；
其中 `.box.l40` 的 `R2 verdict_pending` 是修复前后唯一未消失的 warn。

### 4. `R8 verdict_all_same` 告警
- 审计脚本在本次会话期间新增 R8（≥5 期已开奖行判定全同）。
- 触发 4 处：`#hao012`、`.box.l45`、`#table400916271`、`.box.l67`。

## 十、平特（flat）口径补修：成语平特尾 / 平特一尾（2026-09-30）

用户报障：`271期成语平特尾:【六道轮回】 开:猴35错` —— 第 271 期七个开奖号码的第一个是 36，
尾数 6 与「六道轮回」的「六」一致，应判「准」。

### 10.1 根因

`static/js/068chengyupw.js`（成语平特尾）的命中口径是**只比最后一个特码**：

```js
let tail = code ? code.split('').pop() : '';      // code = codeSplit[codeSplit.length-1]
if (opened && tail && tail === num) { zj = true; }
```

平特（flat）的语义是「本期**七个开奖号码**里任一号码命中即算命中」（后端
`predict.common.flat_tail_hit` / `flat_zodiac_hit`，mode 54/56/43/470/103 均为 `flat_*`），
所以命中落在平码上的期次一律被误判成「错」。本地 dev 库实测 190/185/184/183 四期属于此类。

同一站点其余平特模块（`022pt1w` 平特一尾、`065yiziptx`/`074ptyx` 平特一肖、
`066chengyupx` 成语平特肖、`067sanzipw` 平特三肖）本来就是拿整期 `res_code` / `res_sx` 比对的，
只有成语平特尾退化成特码口径。

### 10.2 修法

| 文件 | 改动 |
| --- | --- |
| `068chengyupw.js` | 命中改为遍历 `codeSplit`（七个开奖号码）比较**末位数字**；命中时把**预测的成语**标黄（命中的号码可能是平码，标黄特码会给出假命中标记）；开奖段仍固定显示本期特码 |
| `022pt1w.js` | 平特一尾的命中由「子串包含」（`getZjIndex(candidate, codeSplit)`，候选尾 1 会被 19 的十位 1 误命中）改为**只比末位数字** |

渲染示例（190 期：`res_code=20,19,38,35,23,42,45`，特码 45）：
`【零珠片玉】(零 → 尾 0) 开:狗45准`，成语标黄（20 是平码、尾数 0）；判「错」的期零黄底。
