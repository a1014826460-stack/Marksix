# 台湾彩固定开奖门禁

适用于十站共享台湾彩面板、公开开奖和历史接口、资料聚合及兼容接口、预测回包和管理接口。香港、澳门保持原有源站公布规则。

## 唯一时间规则

- 排期为北京时间每日 **22:32:00**。以主库本期记录和服务端时间为准。
- 实际揭示锚点为 `max(draw_time, opened_at)`；只有 `opened_at` 缺失/空值才允许回退到有效 `draw_time`。非空坏时间关闭门禁。禁止通过接口参数缩短 **25 秒**间隔。
- 台湾彩必须有有效的计划 `draw_time`，实际开盘时间有效也不能替代缺失或错误的计划。时间必须为日历有效的 `YYYY-MM-DD HH:mm:ss` 或同格式 `T` 分隔符；不能靠宽松日期解析、设备时钟或缓存时间决定放行。
- 期号、彩种、排期、主库状态不能确认时隐藏实际开奖结果。未来真值可以在内部存储/计算，不可直接进入 HTTP 回包。

| 距实际锚点 | 最大公开球数 | 特别号 |
| --- | ---: | --- |
| 小于 0 秒 | 0 | 隐藏 |
| 0–不足 25 秒 | 1 | 隐藏 |
| 25–不足 50 秒 | 2 | 隐藏 |
| 50–不足 75 秒 | 3 | 隐藏 |
| 75–不足 100 秒 | 4 | 隐藏 |
| 100–不足 125 秒 | 5 | 隐藏 |
| 125–不足 150 秒 | 6 | 隐藏 |
| 满 150 秒 | 7（前六球完整才放第七球） | 可见 |

合法数量还受已收到的连续号码前缀约束，缺球不会被猜测或移动特码位置。

## 每个响应与每次展示必须执行

1. 后端台湾最新开奖从主库重建实际数据，再按当前时间裁切。缓存中的期号、时间、号码和 `is_complete` 都不能授权放行；不原地改完整缓存。
2. 历史、资料模块、旧接口和预测中的实际 `res_*`、特码属性、命中判定等，在本期完整门禁开放前隐藏。公开历史还须满足已有的可配置历史延迟（默认 8 分钟）；配置为 0 也不能取消 150 秒底线。管理接口同样不能提前泄露，保留内部写入功能。
3. 嵌套结果自带不同期号时独立核验；没有权威身份的实际结果关闭。预测候选、正文和标签保留。
4. 前端最新开奖代理、站点统一开奖接口及 `wy.json` 独立按本期排期、25 秒规则及校准时间上限裁切。历史代理、JSONP 和历史页面独立过滤尚未完成的期次。当日快照缺少实际开盘证据时不能用作历史兜底。
5. 所有相关 JSON/JSONP 回包使用 `Cache-Control: no-store`。内部缓存不能绕过响应门禁。
6. 面板只由新鲜网络响应校时；`server_now_ms` 与秒字段须一致，随后用单调计时推进。面板必须从 fresh deadline 的 `current_draw_time` 或此前 fresh `next_time` 取得本期权威计划下限；缺少下限时保持空态，不能只信完整号码回包中的时间。会话缓存不能提供时钟或排期，只可恢复权威排期下本期已经合法显示的前缀。
7. 到下一期排期清旧面板；旧期和未来期不能冒充本期。刷新、iframe 重建、睡眠恢复都按共同绝对时间恢复合法进度；已经合法显示的本期球不因短响应或请求失败清空。晚进入不重新从第一球播放，开奖结束后显示完整七球。
8. 管理表单对被隐藏的字段标记 `result_restricted`/`numbers_restricted`。未主动修改时不得回写遮挡后的空值；更新请求遗漏 `numbers` 时保存原值。
9. Nginx 的结果接口必须关闭代理缓存并尊重 `Cache-Control`。只看 HTTP 返回 `no-store` 不足以验收，还须检查实际 `nginx -T`：相关 API 不得启用 `proxy_cache kj_api`，不得通过 `proxy_ignore_headers` 忽略 `Cache-Control`，重复请求不得返回缓存 HIT/STALE/UPDATING。静态资源保留原有缓存策略。
10. 历史 API 的短期号（如 `280`）只能与响应顶层有效年份（如 `2026`）组合核验；保持原显示格式。缺失/错误年份、年份与排期不一致或无效期号仍关闭门禁。不得用设备年份补足未知身份。

## 固定验收

本地必跑 `python scripts/check-taiwan-draw-gates.py`，包含真实 Python 门禁、真实前端面板、实际代理回包和管理表单契约。验证提前/边界、坏锚点、错误完整回包、延迟配置 0、缓存污染、刷新保留、未知身份和衍生结果。任何新增失败都阻止发布。

同时遵守仓库要求：全量后端 `python -m pytest -q`、展示契约、本地展示审计及十站线上展示审计。既有环境失败须与基线逐项核对并记录，不能宣称全量通过。

每次发布前，经用户当轮授权只读核对两节点：`NTPSynchronized=yes`、有效 NTP 源与偏差（目标绝对值不超过 100ms）、单一健康调度租约、无卡住任务、本期未提前打开、22:32 持久任务就绪。发布顺序为后端/API、管理与前端，确保新增排期/时间元信息已生效，再更新依赖它们的代理。任一前置项不满足，不发布。

发布后验证十站共享面板版本一致、各 API 禁缓存，以及实际开奖窗口各阶段的号码数量/特码/历史和派生结果。静态页面需要载入新版本才能使用新增防护。

所有用户共用时间表；操作系统调度和网络传输仍有延迟，不能承诺每台设备在同一毫秒收到数据。延迟只能保守地推迟展示，不能提前开放号码；源数据迟到时显示同步状态并继续轮询。
