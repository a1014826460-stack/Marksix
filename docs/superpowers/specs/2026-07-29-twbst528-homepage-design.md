# 台湾百事通首页设计

## 目标

以 `Zz_amxxc.cp567.cc` 静态包为视觉与 DOM 基线，新增站点 `twbst528`，站点名为“台湾百事通”，主域名为 `www.twbst528.com`。首期将首页接入统一的同源公开 API；静态资料页完整保留，后续按相同契约逐页动态化。

## 范围

- 复制完整供应商静态包至 `frontend/public/vendor/twbst528/`。
- 首页 `index.html` 保留供应商 CSS、结构、卡片、表格与移动端布局；移除外部运行时数据依赖并接入同源数据客户端。
- 建立固定站点配置：台湾彩、澳门彩、香港彩三个玩法；默认台湾彩。
- 建立首页既有 DOM 适配器：只更新既有叶节点，按模块的完整期组渲染。
- 注册前端 manifest、路由、站点索引、适配器注册表、UI 基线和测试。
- 新增后端站点 profile/授权依赖的工作不在本次“前端首期”变更内；前端使用 `siteKey=twbst528`，后端启用前必须为相同 key 建立站点记录及模块授权，不能借用其他站点的 web_id。

## 不在首期范围

- `index1.html`、数字资料页、`history.html` 等资料页的数据化；这些页面保持复制后的静态形态，但会在第二阶段分别审计、映射和动态化。
- 改造供应商视觉设计或重排首页。

## 架构

`/twbst528` 使用现有 `VendorSitePage` iframe 容器加载 `/vendor/twbst528/index.html`。`site-config.js` 是唯一的站点身份来源。`site-data-adapter.js` 通过 `LotterySiteDataClient` 调用同源 `/api/sites/twbst528/draw` 与 `/api/sites/twbst528/prediction-modules`；缓存和请求状态由共享客户端负责。

供应商首页的开奖标签替换为三种统一玩法，并以受控 iframe/既有开奖槽位显示当前开奖数据。预测区域只以稳定的 `tbody` ID、模块标题与其内部 `tr > td` 为选择范围。适配器不得创建、移动、删除或替换 DOM 节点；不得写入 `tr`、`table`、`div` 容器，也不得使用 `innerHTML`。

## 首页映射原则

- 每个映射模块先记录标题、期组数、行列拓扑、期号/预测/开奖结果/命中节点；不以相邻模块或同名模块推断结构。
- 三列历史表保持：第一格期号、第二格预测、第三格“开 + 结果”。每一行是一个期组。
- 命中只复用原有 `span[style*="background-color"]` 等叶节点；不存在该节点时仅更新已有文字节点，不新增高亮标记。
- 没有经批准的后端模块时，对该模块的动态槽位显示“暂无后端资料”，不能保留供应商静态期号、号码、`对/错` 或 `?????`。
- 历史请求数量按首页最大可见期组数计算，最多 20 个去重期号；每个 renderer 自行截断至自己的现有期组数量。

## 站点身份与页面文本

可替换的站点名、域名和 SEO 文本统一从 `siteConfig` 写入既有文本节点，显示“台湾百事通”和 `www.twbst528.com`。供应商的外部广告、外部图片与外部跳转不作为数据源；动态化后的首页不通过外站请求获取开奖或预测资料。

## 验收

- `/twbst528` 可加载供应商首页且视觉容器、导航、页脚结构存在。
- 三个玩法切换会请求对应的 `lottery_type`，并且不会让旧请求覆盖当前玩法。
- 每个首期映射模块只更新其自身的已有槽位；期号连续、无重复，命中保留黄色背景节点。
- 浏览器契约验证模块内的具体单元格、期组数和静态哨兵清除，而不是仅检索页面全文。
- `site:sync-manifests`、`site:validate --site-key twbst528`、UI baseline、adapter registry、站点浏览器契约、TypeScript 和前端构建通过。
