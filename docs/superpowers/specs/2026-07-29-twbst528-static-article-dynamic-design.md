# 台湾百事通静态资料页动态化设计

## 目标

将 `twbst528` 首页高手榜首先链接的 `141.html` 至 `156.html` 接入站点
10（`web_id=10`）的同源公开预测接口。第二阶段以相同的审计与映射方法处理
剩余静态资料页，绝不复用其它站点数据或供应商静态结果。

## 第一阶段页面合同

这 16 页共享一个既有 DOM 拓扑：`#biaoti` 为标题，`.article-content` 内的八个
`p` 是期组，内部已有 `span`、`font` 与黄色命中节点。适配器只写每个期组的最小
文字叶节点，保留每页的作者、日期、标题、标点、颜色、换行和页面布局。

或黑色“错”。

## 架构

新增页面专属 `static-article-data-adapter.js`，读取现有 `site-config.js` 和共享
`LotterySiteDataClient`，由页面路径解析页面合同，并请求
`/api/sites/twbst528/prediction-modules?lottery_type=3&history_limit=8`。所有资料页
仍由供应商 HTML 直接展示；不创建共享运行时、不替换容器，也不访问外部供应商 API。

后端仅扩展站点 10 的授权蓝图，加入第一阶段每个确有页面映射的机制和 mode ID。
公开接口继续按 `web_id=10` 过滤，保证其它站点预测资料不能进入这些页面。

## 第二阶段

已审计并动态化剩余相同资料页拓扑：`15`–`24`、`27`、`30`–`44`、`45`–`49`、
`51`–`60`、`77`–`80`。它们均使用 `.article-content > p` 单期组合同，并映射到
第一阶段已有的精确后端机制；页面只显示自身可见的期组数。

`index1.html` 是另一份带独立开奖标签和整套首页表格的供应商首页副本，不能复用
文章行 renderer；`history.html` 是完整开奖卡片列表，需专门的多期开奖记录 API；
`sx.html` 是生肖年度对照表；`index2.html`、`xyp.html`、`xzy.html`、`by.html`、
`crypto.html`、`seo.html` 是宣传/SEO 页面，不含预测数据槽位。这些非同拓扑页面保留，
待分别建立数据合同，不能以“静态资料页”名称进行泛化替换。

## 验收

- 16 个首页高手榜链接均加载同源 API 的站点 10 数据，八期不重不跳。
- 代表性页面验证期号、预测、开奖结果、命中背景、供应商静态哨兵清除和缺失状态。
- 三种玩法至少验证台湾彩；适配器架构允许以后在页面中加入玩法入口时传递对应
  `lottery_type`。
- 页面与模块授权、公开 API 隔离、静态/浏览器合同��站点验证、TypeScript 和构建通过。
