# 台湾彩未来开奖记录定时自动填写设计

## 目标

让管理员为台湾彩配置是否启用自动填写、保留的未来期数（1..60）和服务器时区下的每日执行时间（HH:mm）。独立 `scheduler-worker` 在到点后自动将未开奖台湾彩期数补足到目标值，使日常维护不再依赖人工新增开奖记录。

## 范围与约束

- 仅作用于 `lottery_type_id=3` 的台湾彩。
- 既有未来开奖记录始终保留：不修改 ID、号码、状态或期号，也不删除。
- 定时设置的目标期数是台湾彩 `is_opened=0` 未来期的总量；已有未来期先计入目标，只有不足部分才新增。手动“自动填写开奖记录”仍按输入值新增对应数量，并跳过已有期号。两种路径均复用现有 `autofill_taiwan_future_draws` 的 `secrets.SystemRandom`、十期位置约束、SQLite/PostgreSQL 事务锁。
- 管理员仍可查看、编辑、删除和手工新增开奖记录；手动“自动填写开奖记录”入口继续作为即时补齐工具。
- 调度按服务器时区执行。当前生产服务器时区为 `UTC`，后台明确展示该时区。

## 配置与 API

使用已有 `system_config` 及变更历史保存三项配置：

- `taiwan_future_autofill.enabled`：布尔，默认 `false`。
- `taiwan_future_autofill.count`：整数，默认 `12`，限制 `1..60`。
- `taiwan_future_autofill.time`：时间，默认 `00:00`，严格为 `HH:mm`。

新增管理员鉴权接口：

- `GET /api/admin/draws/auto-fill-future/settings`：返回当前配置、`UTC` 时区、最近一次任务状态和下次计划时间。
- `PUT /api/admin/draws/auto-fill-future/settings`：原子校验请求字段后保存三项配置，并记录操作者及原因到既有配置历史。

## 持久化调度

新增调度任务类型 `taiwan_future_draw_autofill`，任务键含执行日期，因此同一天只能完成一次。启动和每轮任务调度都会确保当天或下一天存在任务：

- 目标时间未到时，排入当天目标时间。
- 服务在目标时间后启动且当天没有成功/运行中的任务时，立即排入当天任务（补跑）。
- 当天任务正在执行或已经成功时，排入下一天。
- 任务获取、执行记录、失败重试与锁全部复用 `scheduler_tasks`、`scheduler_task_runs` 和 worker 租约。轮询不得重置同日待重试任务的失败信息、尝试次数或延迟；管理页独立返回最近完成/失败结果与最近待执行任务，因此失败结果在次日任务已排入后仍可见。

任务执行时再次读取配置。禁用时不生成任何记录；启用且未开奖未来期数低于目标时才调用领域生成服务。成功后任务运行记录保存概要数量，不存储完整开奖号码。

## 管理界面

“开奖记录管理”页保留即时自动填写控件，并新增“台湾彩自动填写设置”卡片：启用开关、目标期数、每日执行时间、服务器时区、上次任务结果、下次计划时间及保存按钮。加载页面时读取设置；保存时显示成功或服务端校验错误。

## 验证

回归测试覆盖：配置默认值和请求校验、设置 API 的权限与合同、服务启动后的到点补跑、同日幂等、禁用不生成、目标已满足不生成、任务执行调用既有生成服务，以及页面契约。现有未来开奖记录保留行为继续由既有领域服务测试保障。
