# 统一强制公告设计

## 状态

- 日期：2026-08-10
- 状态：已确认，待实施
- 范围：全部公开 Site 页面、Python 公共 API、后台管理界面

## 目标

运营可创建一条在北京时间有效的统一公告，并选择全站或指定 Site。每个命中的
公开页面必须显示同一强制弹窗。用户可关闭本次浏览器会话的弹窗，或明确确认当前
公告版本并在该浏览器不再显示；公告内容、时间或范围变化后必须产生新版本并再次
显示。该功能不得改变开奖、预测、Future Issue 脱敏或既有公开 API 的开奖语义。

## 数据模型与有效性

新增 `forced_announcements` 与 `forced_announcement_sites`。公告拥有不可变 `version`
（保存时随机生成）、标题、经服务端净化的 HTML 正文、范围、北京时间开始/结束、
启用状态、创建/更新时间。时间区间为开始含、结束不含；结束为空代表持续有效。

范围为 `all_sites` 或 `selected_sites`。保存或启用公告时，服务端按每个启用 Site 的
北京时间有效区间检查冲突：任一 Site 在同一时刻只能命中一条公告。冲突拒绝保存，
不能依赖前端隐藏。修改标题、正文、时间或范围时产生新 version；启用状态切换不
重用旧确认状态。

## 公共读取与安全

`GET /api/public/forced-announcement` 通过现有 Site 上下文解析当前 Site，只返回当前
北京时间有效且范围命中的唯一公告：`id`、`version`、`title`、`html`、`starts_at`、
`ends_at`。无有效公告返回 `null`。该响应禁止包含站点列表、后台备注、未生效公告或
Future Issue 任何字段。

正文仅允许白名单 HTML：`p`、`br`、`strong`、`em`、`u`、`ul`、`ol`、`li`、`a`。
链接仅允许 `https:`、`http:` 和相对 URL；移除事件属性、样式、脚本、iframe、图片及
未知标签。净化在服务端完成，前端仅渲染已净化 HTML。

## 前端运行时

在所有 Vendor Site HTML 的共同构建/注入入口加载一个共享 `forced-announcement.js`，
以当前 Site `web`/`site_id` 请求公告接口。它在 DOM 就绪后创建遮罩弹窗，支持：

- 关闭叉：写入 `sessionStorage` 的公告版本键，本次浏览器会话不再显示；
- “我已确认，不再提示”：写入 `localStorage` 的公告版本键，当前浏览器对该版本长期
  不再显示；
- 新 version 不匹配既有键时再次弹出；
- 无关闭叉以外的关闭路径：点击遮罩、Escape、浏览器历史均不得视为确认。

运行时是独立、无状态、失败可忽略的公共读取客户端：公告接口不可用或 HTML 净化
失败时不阻塞页面、开奖读取、预测读取或公开数据加载。

## 后台管理

新增后台“强制公告”列表与编辑页。表单包含标题、受控 HTML、范围、指定 Site 多选、
北京时间开始/结束和启用开关。保存前显示影响 Site；服务端仍负责校验。列表显示版本、
有效期、范围、状态和命中 Site 数。删除或禁用公告后，公共接口立即不再返回它。

## 测试与发布门槛

必须覆盖：北京时间边界、全站/指定范围、有效公告唯一性冲突、版本滚动、HTML 净化、
公共响应最小化、关闭叉会话行为、确认持久行为、所有公开入口注入、以及新增站点自动
加载共享运行时。任何改动仍需通过 prediction-release-review 的 generation、missing-alert、
scheduled-draw、public-redaction 四组回归；公告代码不得访问或记录 Future Issue 真值。
